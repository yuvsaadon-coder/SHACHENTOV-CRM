# שלב 0 — יסודות · דוח סיום

**תאריך:** 18.11.2026 · **מיקום בריפו:** תיקיית `voting/` (אפליקציה נפרדת, ה-CRM לא השתנה)

## מה נבנה
- אפליקציית Vite + React 18 + TypeScript (strict). כל הטקסטים בעברית ב-`src/i18n/he.ts`, ‏RTL עם CSS logical properties.
- **פורט האלגוריתם** ל-`src/lib/algorithm/` (טהור, בלי Firebase). כל 18 הבדיקות של מימוש הייחוס עברו ל-Vitest, ובנוסף **בדיקת השוואה** שמריצה את המימוש החדש ואת מימוש הייחוס על 300 מחזורים אקראיים ומוודאת תוצאה זהה.
- **סקר הרכזים**: בחירת שם → Stepper עם נעילה עוקבת של סלים, פס תקציב, אזהרה מ-90%, שליחה. אותו מפתח טיוטה ב-localStorage כמו באתר הישן.
- **לוח האדמין**: 8 הלשוניות של האתר הישן. התוצאות מחושבות באלגוריתם החדש (§7), כולל סימון תיקו, יישור א'/ב' והצבעות שתוקנו.
- **החלטת הבעלים 18.11.2026:** חצי שנה = **24 שבועות**. סניף שמחלק כל שבוע = 24 חלוקות, כל שבועיים = 12 (`HALF_YEAR_WEEKS`, נבדק ב-`tests/unit/periods.test.ts`, עודכן ב-SPEC §10.3 ו-OQ-10).

## תאימות לאתר הישן
האתר החדש קורא וכותב **בדיוק אותו מבנה** ב-Firestore (`config/main`, `votes/{id}`), כדי ששניהם יעבדו במקביל על אותם נתונים עד המעבר. שיפורים שכבר נכנסו:
- שמירת הגדרות כותבת **שדה אחד** בלבד ולא מחליפה את כל המסמך (D5, חלקית: מוצר בודד עדיין נשמר כחלק מרשימה; תיקון מלא בשלב 2).
- מספר הסבב ומצב פתוח/סגור **נשמרים בענן**, וסבב סגור באמת חוסם רכזים (D4).
- "איפוס סבב" ו"סבב חדש" **מעבירים לארכיון** (`archivedVotes`) עם סיבה, במקום למחוק (D13).
- אין Tweaks Panel, אין קבצי design-canvas (D11). בנייה אמיתית לפרודקשן (D12).
- בלי משתני Firebase האתר עולה ב**מצב הדגמה** (נתונים בדפדפן בלבד, עם פס אזהרה צהוב).

## תסריט הדגמה
1. פותחים את האתר → בוחרים "לאה ליבנת".
2. ממלאים סל א' (למשל 4 פסטה + 4 טונה) → "המשך לסל הבא" → ממלאים את ארבעת הסלים → "שלח הצבעה".
3. "החלף" → "יוחאי אבוטבול" (בקעה): אין ירקות ברשימה.
4. נכנסים ל-`/admin` → "1/14 הצביעו" → "תוצאות משוקללות" / "סל מומלץ" / "ייצוא לספק".
5. "סבבים" → "סגור הצבעה" → בסקר מופיע "ההצבעה סגורה".

## מה **לא** נבדק / לא נעשה
- **מול Firebase אמיתי או Emulator לא נבדק.** שכבת Firestore נכתבה אבל לא הורצה (אין בסביבה Java ל-Emulator ואין גישה לפרויקט).
- **אבטחה לא טופלה** (זה שלב 1): עדיין אין התחברות לאדמין, והחוקים הפתוחים בפרויקט נשארים כפי שהם. `firestore.rules` הוא טיוטה ולא נפרס.
- פריסה ל-Netlify לא בוצעה: צריך ליצור אתר חדש (הוראות למטה). CI ב-GitHub נכתב אבל עוד לא רץ.
- מחזורים, טיוטה בענן, דוחות אקסל: שלבים 2–4.

## הקמת אתר Netlify (פעם אחת, בלי תכנות)
1. Netlify → **Add new site** → **Import an existing project** → GitHub → הריפו `SHACHENTOV-CRM`.
2. **Base directory:** `voting` · **Build command:** `npm run build` · **Publish directory:** `voting/dist`.
3. **Site configuration → Environment variables:** להוסיף את ששת ערכי `VITE_FIREBASE_*` (הרשימה ב-`voting/.env.example`; הערכים מופיעים ב-`firebase-config.js` של האתר הישן, הם לא סוד).
4. Firebase Console → Authentication → Settings → **Authorized domains** → להוסיף את כתובת האתר החדש.
